This is the guide for Matinee v0.1.6. Read the guide for the latest release (v0.1.10).

Kubernetes

Matinee has a Helm chart. It runs the server with a bundled PostgreSQL whose credentials are generated into a Secret on the first install, so there’s nothing to set up, and it works the same under Argo CD or Flux.

A starting point

Section titled “A starting point”

Each entry in media mounts any Kubernetes volume (NFS, SMB through a CSI driver, a PVC, a host path) read-only under mediaRoot (/media), with an optional subPath. When you add a library, the folder picker opens there.

The values that matter

Section titled “The values that matter”
Value Default What it’s for
ingress.* off How you reach Matinee. Set your host and TLS.
tmdb.existingSecret empty The Secret with your TMDB key.
media none Your media folders.
downloads.persistence on, 50Gi Where downloads for the apps are prepared. Set storageClass or existingClaim.
plugins.persistence on, 5Gi Where installed plugins and what they keep live. Set storageClass or existingClaim.
postgresql.enabled true The bundled database. To use your own, turn it off and set database.url or database.existingSecret.
discovery.* on Lets the apps find the server at home; see below.
remoteAccess.* off Watching away from home when the ingress only works at home; see below.
gpu.type none vaapi (AMD, Intel) or nvidia for hardware transcoding.
nodeSelector, tolerations, affinity none Keep Matinee on the node with the GPU, for example.
env none Any other setting, such as MATINEE_RATING_COUNTRY.
resources none Requests and limits. Transcoding without a GPU wants several CPU cores.

Transcodes and the image cache use a local emptyDir, so they’re fast and never land on network storage.

Replicas

Section titled “Replicas”

Run one replica for now: a transcode in progress lives in the pod that started it. More replicas work with service.sessionAffinity: ClientIP, so each device keeps talking to the same pod.

The apps at home

Section titled “The apps at home”

The chart runs a small announcer on a node’s host network so the apps find the server at home, pointing them at your ingress address. It also opens port 7172 on Matinee’s node (discovery.homePort) as the home network’s own way in, so devices at home can watch without signing in while everything through the ingress signs in. Set discovery.homePort=0 to turn that off, discovery.url if your ingress is managed outside the chart, and discovery.enabled=false to keep the server unlisted.

Watching away from home

Section titled “Watching away from home”

If your ingress is reachable from the internet, it’s the way in from outside and there’s nothing to set. If it only works at home, set remoteAccess.enabled=true and Matinee sets up remote access itself: it asks your router for a port and gets its own certificate. Talking to the router takes the node’s own network, so the pod then runs on its node’s host network, with ports 7171, the home port and remoteAccess.port (7443) opened on that node. Its key, certificate and Matinee Connect subscription go on a small volume (remoteAccess.persistence) so the server keeps its identity across restarts. Don’t set MATINEE_PUBLIC_URL alongside it.

Following the latest build

Section titled “Following the latest build”

To try each change as it lands, point Argo CD at the edge branch. It moves to a commit on main only once that commit’s checks pass and its image is published, and the chart from that commit runs the image built from it:
