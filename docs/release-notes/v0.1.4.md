Playback now rides out server restarts and updates, and the phone and TV apps can switch audio tracks while you watch.

### New

- **Playback keeps going through restarts and updates.** When the server restarts, the web player says **The server is restarting**, waits for it to come back, and picks up at the same spot with a note such as **The server was updated to v0.1.4**. The phone and TV apps do the same from version 1.0.12.
- **Audio track picker**: the apps can now choose any of a file's audio tracks, even when the server has to convert the video.
- **The TV remote works like a TV's own player**, with Audio, Subtitles and Sleep timer buttons under the progress bar. See [Watching on a TV](https://matinee.yeix.io/docs/apps/phone-and-tv/).

### Better

- On shutdown the server tells players it's restarting before it stops, and finishes requests already in flight. `MATINEE_DRAIN_DELAY` and `MATINEE_SHUTDOWN_TIMEOUT` tune this.
- `/health` reports whether the server is restarting and when it last started.
- Helm chart: `strategy` and `shutdown` settings with a matching termination grace period, and the setup job now runs on Matinee's own node, so upgrades are shorter.

### Updating

Packages, the Docker image and the Helm chart update as usual. See [Updating](https://matinee.yeix.io/docs/getting-started/updating/), including updating while people are watching.
