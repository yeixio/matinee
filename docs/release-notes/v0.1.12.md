Find out about trouble on your server before anyone else does.

### New

- **Alerts**: Settings → Server health → Alerts tells admins when a disk is nearly full, a library folder can't be read, errors pile up, transcodes keep failing, or the server restarts (and whether it was updated or stopped without shutting down cleanly). Alerts go by email, Discord, ntfy, Home Assistant or any JSON webhook, straight from your server. Disk and folder alerts send an all-clear when things are back, each rule can be turned off or tuned, and **Send a test alert** checks every channel. See [Alerts and metrics](https://matinee.yeix.io/docs/server/alerts/).
- **Prometheus metrics**: turn on `/metrics` with a bearer token to chart Matinee in Grafana or any Prometheus setup. See [Prometheus metrics](https://matinee.yeix.io/docs/server/alerts/#prometheus-metrics).

### Better

- **Quieter hardware transcoding**: on read-only filesystems, such as the Docker image and the Helm chart, FFmpeg now gets a writable cache folder inside Matinee's data folder, so VAAPI transcodes no longer warn about the shader cache.

### Updating

Packages, the Docker image, the Helm chart, the Mac app and the Windows app update as usual. See [Updating](https://matinee.yeix.io/docs/getting-started/updating/) in the guide. Alerts start once an admin adds somewhere for them to go, and metrics stay off until an admin turns them on.
